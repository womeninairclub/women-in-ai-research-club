Hackathon Structure

Two-Stage Format

01

Idea Submission & Screening

Participants review the published problem statements and submit or pitch their proposed solution ideas.

Only teams selected through the screening stage proceed to the Main Hackathon / Final Development Round.

02

Main Hackathon

Selected teams advance to the final round and develop their proposed solutions during the designated hackathon development period on 20 October 2026.

Challenges

Problem Statements

Problem Statement Release

The official problem statements will be published on the Women in AI, Research, Innovation & Entrepreneurship Club's official website on 18 October 2026.

  • Study the problem statements.
  • Understand the requirements.
  • Identify the challenge you wish to address.
  • Develop an initial solution concept.
  • Prepare your idea / proposal.
Participants may think about and plan their proposed approach during this period. However, the main hackathon development phase begins only after teams are selected for the final round.
Stage 1

Idea Submission & Screening

Required Idea Information

  • Team name
  • Team members
  • Selected problem statement
  • Problem understanding
  • Proposed solution
  • Innovation / novelty
  • Proposed technology / AI approach
  • Expected impact
  • Brief implementation plan

Screening & Selection

  • Understanding of the problem
  • Relevance of the proposed solution
  • Innovation
  • Feasibility
  • Appropriate use of AI / technology
  • Potential impact
  • Clarity of the proposed approach

Only selected teams will proceed to the Main Hackathon / Final Development Round.

Participation

Team Formation

Team Rules

  • Participants may participate individually or in teams.
  • Maximum team size: 4 participants.
  • Each team must designate one Team Leader.
  • The Team Leader is the primary point of contact with the organizing team.
  • Each participant may participate in only one competing team.
  • Team members must be declared during registration / idea submission.

Team Responsibility

Teams are responsible for ensuring that their team information is accurate and consistent across registration, idea submission and final submission.

Participants should ensure that their contributions and project information are represented accurately.

Development

Development Rules

Originality & Pre-existing Work

  • Submitted work must represent the team's own work.
  • Plagiarism, copied solutions and misrepresentation are not permitted.
  • Entirely pre-built projects should not be submitted as newly developed hackathon work.
  • Open-source libraries, frameworks, APIs, public datasets and pretrained models may be used where legally permitted.
  • Significant pre-existing components should be disclosed where requested.

AI-Assisted Development

  • AI-assisted development tools are permitted as described in the official rules.
  • Teams remain responsible for their submitted work.
  • Significant use of AI tools should be disclosed where requested.
  • Participants must comply with the terms of the AI tools they use.
Code Submission

GitHub Repository Requirements

Each final-round team must maintain its project in a GitHub repository. The repository must be accessible to the judges.

  • Source code
  • README.md
  • Requirements / dependencies
  • Installation instructions
  • Usage instructions
  • Documentation
  • Dataset information
  • Model information
  • Screenshots
  • Demo information
  • Credits / attributions
Security: Do not upload passwords, API keys, access tokens, private credentials, confidential documents or sensitive personal information to a public repository.

Stage 2

Final Project Submission

What You Need to Submit

  • GitHub repository URL
  • Team details
  • Selected problem statement
  • Project description
  • Demo link / video, where applicable
  • Required documentation
  • Other information requested by the organizers
Important: The GitHub repository and the official submission form together constitute the final submission.
Final Project Submission Download Submission Format
Final Submission Deadline: The final submission deadline will be announced as part of the official 20 October 2026 hackathon schedule.
Before You Submit

Final Submission Checklist

  • Correct team details
  • Correct selected problem statement
  • Source code uploaded
  • README completed
  • Requirements / dependencies included
  • Dataset and model information provided
  • External resources acknowledged
  • Demo prepared, where applicable
  • GitHub repository accessible to judges
  • No passwords, API keys or sensitive credentials uploaded
  • Official submission form completed
  • Final submission completed before the announced deadline
Presentation

Project Demonstration & Final Pitch

Final-round teams may be required to demonstrate and pitch their completed solutions to the judges.

  • The problem
  • The proposed solution
  • How the solution works
  • Technology / AI techniques used
  • Key features
  • Results
  • Impact / use case
  • Future scope
Evaluation

Judging Criteria

Problem Understanding

How clearly the team understands the assigned challenge.

Innovation

Originality and creativity of the solution.

Technical Implementation

Quality and appropriateness of the implementation.

Use of AI

Meaningful and appropriate use of AI/ML or related technologies.

Functionality

How effectively the proposed solution works.

Practicality & Impact

Potential real-world usefulness and impact.

Scalability

Potential for further development or deployment.

Presentation

Clarity of documentation, demonstration and final pitch.

The final judging criteria and weightage may be communicated separately by the organizers.
Evaluation Process

How Projects Are Reviewed

  • Review GitHub repositories
  • Examine source code
  • Review documentation
  • Test the submitted project where feasible
  • Watch demonstrations
  • Listen to the final pitch
  • Ask questions
  • Request clarification
Participants should remain available during the judging period.
